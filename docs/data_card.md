production traffic and not natural user behaviour; the user turns are synthetic
and are delivered through a subagent messaging channel that adds harness framing
(decision log D10).

## What is stored in this repository

* Sanitised controlled transcripts (`data/controlled/transcripts/<id>.jsonl`):
  conversation content, tool calls/results, timestamps, model name and token usage
  only. Harness internals and internal ids are removed (decision log D9).
* Task directories (`tasks/<id>/`): manifests, provenance, snapshot manifests,
  contracts, candidate patches, verifier tests and specs.
* Not stored: base snapshots of the source repositories (rebuilt from the pinned
  public commit with `tracecontract snapshot`), raw unsanitised transcripts, any
  gated or third-party conversation data.

## Licensing and permissions

* Repository code in candidate patches and snapshots is covered by each source
  repository's licence (all MIT here); attribution is the repository URL and commit.
* Controlled transcripts and study-authored files: authored for this study; the
  repository's licence decision is pending (see `STATUS.md`).
* SWE-chat, if used: dataset licence ODC-BY-1.0 (database); conversation contents
  may embed third-party material; gated access requires each user to accept the
  dataset terms. Raw SWE-chat transcripts will not be redistributed; tasks would
  reference them by `session_id` and dataset revision. The dataset's data-removal
  policy will be honoured by re-checking session ids against the current release
  before publication.

## Personal information

Controlled sessions contain no third-party personal data by construction. Paths
in transcripts refer to this study's sandbox. The repository owner's identity
appears only as the git commit author.

## Known biases and limitations

* Every model-generated artifact (agent sessions, contracts, tests, attacks,
  alternatives, near misses) comes from the same model family, which can correlate
  errors across conditions and with the labels' proposals.
* Scenarios were designed by the study to contain corrections; natural correction
  frequency and content are not represented.
* Base snapshots may be approximate (e.g. generated build artefacts such as
  hatch-vcs `_version.py`); approximations are listed in each `snapshot.json`.
