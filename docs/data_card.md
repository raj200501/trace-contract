production traffic and not natural user behaviour; the user turns are synthetic
and are delivered through a subagent messaging channel that adds harness framing
(decision log D10).

## Held-out candidates and labels (per task)

Every task has the same pool:
* The pre-correction state was captured during the session, before any verifier
  existed. Its edits appear, abbreviated, in the session text that B2's generator and
  the full-session contract proposer read.
* The alternatives and near misses were generated after all of the task's evaluated
  verifiers were frozen (CS-04's B1 was re-selected afterwards; decision log D31), by
  separate agents, each exporting its own workspace directory. The agents ran as the
  same user in the repository checkout, so verifiers and registered candidates were
  readable. They were told not to read them. An audit of the tool inputs of every
  generator whose output was registered found no forbidden read; tool outputs are not
  inspected.

Exceptions (decision log D31, D37, D40, D41):
* near-miss generators had, and ran, B1's test files (the test hunks of the reference
  diff);
* three held-out candidates duplicate a development attack used in their family's C4
  audit. `CS-04-pre-correction` and `CS-04-eval-nm-2` have the same graded patch as
  `CS-04-dev-attack-full_session-a3`. `CS-01-eval-nm-5` differs from
  `CS-01-dev-attack-full_session-a3` by one docstring line (`tasks/*/labels/duplicates.json`).
  Neither C4 audit made a revision;
* the reference checks were written while the pools were being generated (CS-01,
  CS-02, CS-04) or just before (CS-03); CS-02's were revised after its pool was
  complete;
* the CS-01 and CS-02 held-out prompts differ from the CS-03 and CS-04 ones;
* agents shared a scratch directory that held held-out material;
* the hash of each verifier's scored check list was added after the run `pilot-v0.3`.

Proposals by rule D19 (`tasks/*/candidates/*.json`, labeler
`builder:refcheck+regression+construction:v1`) are **not** human labels.

* An independent model check of every held-out candidate is in
  `tasks/*/labels/construction_checks.json`. It is advisory and never changes a
  label.
* Candidates needing human review are listed in `tasks/*/labels/review_queue.json`.
  The queue file contains no verifier outcome.
* Two independent model mappings of each recovered contract to the reference
  contract are in `tasks/*/contracts/mapping{,2}_*.json`.

## What is stored in this repository

* Sanitised controlled transcripts (`data/controlled/transcripts/<id>.jsonl`):
  conversation content, tool calls/results, timestamps, model name and token usage
  only. Harness internals and internal ids are removed (decision log D9, D38). The
  session agent's thinking text is kept as recorded: 178 thinking blocks, 111 of
  them empty.
* Task directories (`tasks/<id>/`): manifests, provenance, snapshot manifests,
  contracts, candidate patches, verifier tests and specs.
* Not stored: base snapshots of the source repositories (rebuilt from the pinned
  public commit with `tracecontract snapshot`), raw unsanitised transcripts, any
  gated or third-party conversation data.

  dataset terms. Raw SWE-chat transcripts will not be redistributed; tasks would
  reference them by `session_id` and dataset revision. The dataset's data-removal
  policy will be honoured by re-checking session ids against the current release
  before publication.

## Known biases and limitations

* Every model-generated artifact comes from the same model family. This covers
  the scenarios and reference contracts that define the labels, agent sessions,
  contracts, tests, attacks, alternatives, near misses, reference checks, label
  proposals, construction checks and requirement mappings. It can correlate errors
  across conditions and with the label proposals.
* In two of the four controlled sessions (CS-02, CS-03), the agent's pre-correction
  state passes the reference checks and the regression norm, so rule D19 labels it
  valid: the agent had already done most of what the correction asked. For CS-03
  the independent check finds divergences on non-ASCII all-caps input only (Turkish
  dotted İ, circled capitals) and disputes the label. The
  "rejected" state is therefore not automatically a negative.
* Scenarios were designed by the study's AI agent to contain corrections; natural
  correction frequency and content are not represented.
* Base snapshots may be approximate (e.g. generated build artefacts such as
  hatch-vcs `_version.py`); approximations are listed in each `snapshot.json`.
