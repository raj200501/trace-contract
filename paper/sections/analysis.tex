\section{Qualitative analysis}
\label{sec:analysis}
\paragraph{Reward inversion when a correction retracts a request (\texttt{humanize}).} The first request asked \texttt{naturalsize} to drop a trailing ``.0'' by default. The correction kept the default output unchanged and made trimming opt-in. The initial-only contract faithfully encodes the first request, and four of its five scored requirements contradict the reference. The verifiers built from it therefore:
\begin{itemize}
\item reward the agent's own pre-correction state, the one the user rejected;
\item reject both independently written valid alternatives;
\item reject the reference solution.
\end{itemize}
This is the failure the problem statement predicts (the reward points at the rejected behaviour), together with one it does not name: the reward also points away from the wanted behaviour. The predefined audit detects the inconsistency (the reference fails), but a revision that stays faithful to the contract cannot repair it.

\paragraph{Missing edge cases when a correction adds requirements (\texttt{more-itertools}).} The first request added a \texttt{step} argument. The correction added negative steps, an error for \texttt{step=0}, the positional \texttt{ordering} argument and lazy groups, and kept the default output unchanged. The initial-only verifiers accept:
\begin{itemize}
\item the pre-correction state, where \texttt{step=0} silently returns groups;
\item the near misses that break negative steps, the zero-step error or laziness.
\end{itemize}
They reject only the near miss that breaks positional ordering, which also breaks existing behaviour. Every correction-aware condition rejects all four invalid near misses and the pre-correction state.

\paragraph{When the first request already implies the correction (\texttt{tinydb}).} For an atomic-write request, the contract proposer inferred from the first message requirements covering everything the user said later:
\begin{itemize}
\item reads through the same instance see the write;
\item the bytes are unchanged;
\item no temporary files are left behind;
\item the original file is intact after a failure.
\end{itemize}
These appear as \emph{inferred} requirements, which our acceptance gate requires a human to confirm. Initial-only and correction-aware verifiers then make identical decisions. The ``information lost'' by initial-only reconstruction is a property of the session \emph{and} the proposer, not of the session alone.

\paragraph{When the agent anticipates the correction (\texttt{inflection}, \texttt{tinydb}).} In two of four sessions, the agent's state before the correction passes the reference checks and the regression norm, and the rule labels it valid. In \texttt{inflection}, for example, it had already handled all-uppercase input and kept the helper functions unchanged. The agent's state then already met what the correction asked for, and the rule treats the observed state as a valid candidate. For \texttt{inflection}, the independent check disputes that label: it finds divergences from the reference, limited to non-ASCII all-caps input. Whether ``behaves as before'' extends to the Turkish dotted~İ and circled capital letters is exactly the kind of judgement our labels must leave to humans.

\paragraph{Two failure modes of repository tests.} Repository tests taken at the reference state, which include the session agent's own tests, fail in both directions:
\begin{itemize}
\item They \emph{under-specify} the correction's invariants. They accept near misses that break custom formats or rounding in \texttt{humanize}, negative steps in \texttt{more-itertools}, and all-uppercase input and unchanged helper behaviour in \texttt{inflection}.
\item The tests the session agent added \emph{over-specify} the reference's implementation; all four false rejections come from them. They reject valid alternatives that lack a private reopen hook or the reference's clean-up of stale temporary files, and one that splits CamelCase acronyms differently.
\end{itemize}
The second mode also rejects the valid \texttt{tinydb} pre-correction state.

\paragraph{The hard cases escape most verifiers (exploratory).} The near misses that the rule marks ambiguous are those whose violation appears only in a specific setup. The independent reference checks used for labeling miss them, so the rule cannot confirm them. Most verifiers miss them too:
\begin{itemize}
\item \texttt{more-itertools}: floating-point positions in the default grouping. Every condition accepts it.
\item \texttt{tinydb}: a relative database path followed by \texttt{os.chdir}. Every generated-test condition accepts it, including both correction-aware ones.
\item \texttt{inflection}: plural acronyms. Accepted by both correction-aware verifiers, B2 and B1, but rejected by both initial-only ones.
\end{itemize}
The other two ambiguous \texttt{inflection} near misses (acronyms joined by underscores; all-uppercase input with digits or symbols) are rejected by both correction-aware verifiers. If the construction claims are correct, excluding these candidates makes the headline rates optimistic about every condition. Settling that needs human labels and verifiers that probe the setup space explicitly.
