\section{Qualitative analysis}
\label{sec:analysis}
\subsection{Fresh-agent attempts (\texttt{\FRESHRUN})}
\label{sec:analysis-fresh}
% Source: docs/decision_log.md D62 (error analysis read from the patches, the verifier tests and the grader's per-check output).
\paragraph{A loud inversion and a silent loss.} In CS-01, C1 and C2 encode the request that the correction retracted: drop a trailing ``.0'' by default. They fail the reference on 12 of their 14 checks, pass only the checks of the one requirement the correction kept, and accept all 10 \texttt{u1} attempts; this gives 10 of C1's 24 false acceptances and 10 of its 13 false rejections (D62). A rule that a verifier must pass its reference would catch this case, which is the oracle-gated view of \S\ref{sec:results-fresh}. In CS-03 and CS-04 the loss is silent: C1 passes both references and still accepts 14 of the 17 correction-violating attempts there, against 0 of 17 for C3.

\paragraph{Two label artefacts.} In CS-02, D19 labels two \texttt{u1} attempts invalid only through the regression norm: the one failing base test asserts on a private attribute that both attempts deliberately removed, and both pass all 28 reference checks and the independent labeler. They are the whole false acceptance of C3, C4 and B2 (2 of 29 invalid units each); no CS-02 \texttt{u1} attempt violates a correction requirement (D62).

\paragraph{The audit over-specifies.} In CS-03 the single audit revision of C4 added two checks that fix the answers of one development attack, and of the reference, on edge cases that the contracts leave open (contractions, digits and underscores in all-caps words). They cause all 6 of C4's false rejections that C3 does not make. The audit record showed no findings after one iteration and did not show that checks were added; audit records now keep every failing check and every check a revision adds or removes (D62).

\paragraph{Repository tests carry the session agent's tests.} All 34 of B1's false rejections come from the 40 checks that the session agent added to the reference state's test files; none comes from the base commit's tests or from the environment. The base tests alone accept 17 of the 29 invalid attempts and, being D19's regression norm, cannot reject a valid one (D62).

\paragraph{What survives if the improvement is zero.} The information-loss contrast is mechanical and does not depend on the audit; on this stratum the audit is a cost; B2 equals C3 and C4 on false acceptance; and the B1 result is about agent-added tests. C3's false acceptance is also only as low as the labels let it be: a violation that no reference check exercises is labelled valid under D19, so no verifier is ever charged with accepting it.

\subsection{Construction pilot (\texttt{\PILOTRUN})}
\label{sec:analysis-pilot}
\paragraph{Reward inversion when a correction retracts a request (\texttt{humanize}).} The first request asked \texttt{naturalsize} to drop a trailing ``.0'' by default. The correction kept the default output unchanged and made trimming opt-in. The initial-only contract faithfully encodes the first request, and four of its five scored requirements contradict the reference. The verifiers built from it therefore:
\begin{itemize}
\item reward the agent's own pre-correction state, the state before the scripted correction;
\item reject both independently written valid alternatives;
\item reject the reference solution.
\end{itemize}
This is the failure the problem statement predicts (the reward points at the behaviour the correction ruled out), together with one it does not name: the reward also points away from the wanted behaviour. The predefined audit detects the inconsistency (the reference fails), but a revision that stays faithful to the contract cannot repair it.

\paragraph{Missing edge cases when a correction adds requirements (\texttt{more-itertools}).} The first request added a \texttt{step} argument. The correction added negative steps, an error for \texttt{step=0}, the positional \texttt{ordering} argument and lazy groups, and kept the default output unchanged. The initial-only verifiers accept:
\begin{itemize}
\item the pre-correction state, where \texttt{step=0} silently returns groups;
\item the near misses that break negative steps, the zero-step error or laziness.
\end{itemize}
They reject only the near miss that breaks positional ordering, which also breaks existing behaviour. Every correction-aware condition rejects all four invalid near misses and the pre-correction state.

\paragraph{When the first request already implies the correction (\texttt{tinydb}).} For an atomic-write request, the contract proposer inferred from the first message requirements covering everything the user said later:
\begin{itemize}
\item reads through the same instance see the write;
\item the bytes are unchanged;
\item no temporary files are left behind;
\item the original file is intact after a failure.
\end{itemize}
These appear as \emph{inferred} requirements, which our acceptance gate requires a human to confirm. Initial-only and correction-aware verifiers then make identical decisions. The ``information lost'' by initial-only reconstruction is a property of the session \emph{and} the proposer, not of the session alone.

\paragraph{When the agent anticipates the correction (\texttt{inflection}, \texttt{tinydb}).} In two of four sessions, the agent's state before the correction passes the reference checks and the regression norm, and the rule labels it valid. In \texttt{inflection}, for example, it already handled ASCII all-uppercase input as before and left the helper functions' output unchanged. By the rule's checks, the agent's state already met what the correction asked for, so the rule treats the observed state as a valid candidate. For \texttt{inflection}, the independent check disputes that label: it finds divergences from the reference, limited to non-ASCII all-caps input. Whether ``behaves as before'' extends to the Turkish dotted~İ and circled capital letters is exactly the kind of judgement our labels must leave to humans.

\paragraph{Two failure modes of repository tests.} Repository tests taken at the reference state, which include the session agent's own tests, fail in both directions:
\begin{itemize}
\item They \emph{under-specify} the correction's invariants. They accept near misses that break custom formats or rounding in \texttt{humanize}, negative steps in \texttt{more-itertools}, and all-uppercase input and unchanged helper behaviour in \texttt{inflection}.
\item The tests the session agent added \emph{over-specify} the reference's implementation; all four false rejections come from them. They reject valid alternatives that lack a private reopen hook or the reference's clean-up of stale temporary files, and one that splits CamelCase acronyms differently.
\end{itemize}
The second mode also rejects the valid \texttt{tinydb} pre-correction state.

\paragraph{The hard cases escape most verifiers (exploratory).} The near misses that the rule marks ambiguous are those whose violation appears only in a specific setup. The independent reference checks used for labeling miss them, so the rule cannot confirm them. Most verifiers miss them too:
\begin{itemize}
\item \texttt{more-itertools}: floating-point positions in the default grouping. Every condition accepts it.
\item \texttt{tinydb}: a relative database path followed by \texttt{os.chdir}. Every generated-test condition accepts it, including both correction-aware ones.
\item \texttt{inflection}: plural acronyms. Accepted by both correction-aware verifiers, B2 and B1, but rejected by both initial-only ones.
\end{itemize}
The other two ambiguous \texttt{inflection} near misses (acronyms joined by underscores; all-uppercase input with digits or symbols) are rejected by both correction-aware verifiers. If the construction claims are correct, excluding these candidates makes the headline rates optimistic about every condition. Settling that needs human labels and verifiers that probe the setup space explicitly.
