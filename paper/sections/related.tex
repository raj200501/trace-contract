\section{Related work}
\label{sec:related}
% Written from docs/research_brief.md (reviewed draft) and docs/research/review_*.md. Every claim
% below matches a verified finding there; every key is in references.bib. Search not exhaustive.

\paragraph{Problem statement.} An industry essay states the hypothesis we test: ``Preserving the initial prompt alone may produce a task that rewards precisely the behavior the user rejected.'' It reports no method, data or measurement \cite{guo2026production}.

\paragraph{Tasks from sessions and traces.} Trace2Eval reconstructs evaluation instances (a distilled request, a recovered workspace and a containerised environment) from consented coding-agent sessions and scores artifacts with an agentic rubric judge rather than task-specific executable tests \cite{trace2eval}. SWE-Together curates repository-level tasks from recorded sessions, including SWE-chat sessions \cite{swechat}. It replays later user intents through a simulator and scores tasks with test gates and a rubric judge, and it notes that execution-only scoring can miss requirements introduced later in the interaction or reject valid alternative implementations \cite{swetogether}. AfterVibe derives graders from a company's internal coding-assistant sessions, including the developer's corrections; its conversation-derived flexible tests still pass 58\% of pre-change (parent-commit) states \cite{paltenghi2026aftervibe}. REAP restricts itself to single-turn production conversations \cite{jha2026reap}. VibeSWEBench converts human--agent failure sessions into single-turn tasks while preserving the human's corrective signals, graded by human-validated test suites \cite{islam2026vibeswebench}. traj2envs turns agent trajectories into environments gated by an automatic trial matrix and mutant kill rates. Its first-request family keeps only tests that pass on the agent's project at the end of the first request, so whenever the next user message is a correction, the resulting verifier accepts the state the user corrected \cite{huggingface2026traj2envs}. Environment-synthesis pipelines build tasks from commits, pull requests or injected bugs and check their verifiers against gold patches or hidden tests \cite{yang2025swesmith,jain2025r2egym}. None of these works reports false-acceptance or false-rejection rates of executable verifiers against independent human labels of candidate solutions.

\paragraph{Correction-aware statements and audited test suites.} SessionFarmer is the closest work \cite{lu2026harvesting}. It reconstructs executable tasks from SWE-chat sessions and writes task statements that consolidate the requirements still in effect at the end of an episode, citing the supporting user turns. On multi-session tasks, statements written from the first message alone fully cover 26\% of a reference ledger's requirements, against 75\% for full-episode statements. It also scores its initial and refined test suites on the same held-out evaluation rollouts: refinement lowers false-negative rates by 32--34 points and raises false-positive rates by 16.2--17.5 points. These rates are measured against labels from an LLM judge, on 30 tasks selected because refinement changed the suite. SessionFarmer does not generate verifiers from the opening request, does not score the session's own pre-correction states, and has no human patch labels. A with/without-audit comparison on a shared held-out pool is therefore not new; we claim only its human-labelled form, anchored on pre-correction states and crossed with the source of the contract. Agentic Auto-Rubrics, an anonymous ICLR 2027 submission, compiles reaction-masked multi-turn coding sessions into active requirements and atomic rubrics for an agentic LLM verifier \cite{anonymous2026agentic}.

\paragraph{Later requirements and false acceptance.} Several works show that verifiers lacking a later requirement accept outputs that violate it. In PersonaCodeBench, 20.5\% of complete native-test passes fail the recorded persona criteria, which are synthetic, frozen before evaluation and judged partly by LLMs \cite{wang2026personacodebench}; it is the closest precedent for our controlled sessions. SWE-Gate derives constraints from pull-request review comments and finds that 221 of 644 functional-test passes violate them, on synthesized tasks \cite{he2026swegate}. On real researcher--agent sessions, ARE-bench holds deliveries and LLM verdicts fixed and narrows only its checklist: omitting inherited and anchored requirements inflates strict success from 28--40\% to about 69\%, while adding items discovered through later rework moves it by less than one point \cite{lin2026arebench}. Synthetic evolving-requirement benchmarks require new checks to fail on the previous stage's implementation \cite{feng2026benchmarking,zhan2025sreval}. SWE-WhatIf replays recorded sessions with an agent told to repeat the actions the user pushed back on, but it does so to validate a user simulator under an LLM goal judge, not a verifier \cite{kim2026swewhatif}. TellOnce compiles user corrections into checks that govern future tasks rather than the task in which they were given \cite{zhou2026tellonce}.

\paragraph{Verifier fidelity.} VerifierBench scores generated verifiers on held-out pools of valid alternatives, unfinished states, near misses and hacks, using construction labels \cite{yin2026verifierbench}. Hacker-fixer loops harden benchmarks against held-out attackers and track benign pass rates as a false-rejection proxy \cite{zhong2026hardening}. SWE-ABS strengthens tests with mutants and counts equivalent mutants that fail as false negatives \cite{yu2026sweabs}. Audits of SWE-bench find patches that pass the tests but are incorrect \cite{wang2025are,yu2025utboost}. Two-sided metrics against labelled pools are established for algorithmic coding \cite{wang2025codecontests,he2025hardtestgen}. Human-labelled grader errors have been reported for LLM judges and auditors \cite{min2026tracedance,lv2026realclawbench} and for requirement-level judgments \cite{wang2026personacodebench}.

\paragraph{Positioning.} In the works we reviewed, each component of our design has at least a partial precedent. We are not aware of a study that combines three elements: (i) verifiers generated by one frozen procedure from initial-request-only and correction-aware contracts; (ii) one frozen, held-out candidate pool whose anchor negatives are the session's own user-rejected pre-correction states, together with independent valid alternatives and near misses; and (iii) independent human labels of the candidates. Our claim is limited to this conjunction, and the audit and the two baselines are comparison arms within it. The search was not exhaustive, several of the closest works appeared in November 2026, and two related works could be read only at abstract level \cite{anonymous2026agentic,islam2026vibeswebench}. With controlled sessions and model-proposed labels only, the current draft can report descriptive results only.
