\section{Annotation guide}
The guide for human reviewers is \texttt{docs/annotation\_guide.md} (v0.4). It covers:
\begin{itemize}
\item contract review: evidence, kind, status, supersession, observability;
\item candidate labels, made from a blinded review packet (\texttt{tracecontract review-packet}, described below);
\item label values: valid, invalid with violated requirement ids or \texttt{REGRESSION}, or ambiguous;
\item two reviewers per task, each under a pseudonymous id (\texttt{R1}, \texttt{R2}, \dots), who each record their contract reviews, their labels and an origin guess per candidate in their own label file for the task;
\item merging once every task has two complete reviews (\texttt{tracecontract merge-reviews}), and adjudicating disagreements: a candidate whose reviewers give different label values has no final label until an adjudicated label is added;
\item the review queue and the evidence a reviewer may consult only after the labels are merged.
\end{itemize}
Per task, the packet holds the user turns of the session, the reference contract, and each held-out candidate's change and file state under an unguessable random id, in shuffled order. Candidates with identical diffs share one id. The packet names no candidate id, origin, description, proposal or verifier outcome, and the key that maps ids to candidates stays with a coordinator. It hides the origin field but not the origin, which a reviewer can still infer from the content: the user's corrections describe the agent's first attempt, near misses resemble each other and the reference, and in \texttt{tinydb} the diff structure differs by origin. The merge reports how often the origin guesses are right, as a measure of how blind the labels are; the guesses are never used as labels. The procedure has not been used yet.

\section{Example task: \texttt{humanize} (CS-01)}
\begin{enumerate}
\item The user asks that \texttt{naturalsize} drop a trailing ``.0''.
\item The agent changes the default output.
\item The user corrects. The default output must stay exactly as before, because templates and snapshot tests depend on it. Trimming becomes an opt-in keyword argument. Calls with a custom \texttt{format}, including positional ones, must not change.
\end{enumerate}
The reference contract therefore contains five intended requirements, and the default-trimming requirement of the first request is \emph{superseded}. The initial-only contract keeps it, so its verifiers reward the pre-correction state and reject every candidate that honours the correction (Table~\ref{tab:matrix}). The correction-aware contract marks it superseded and scores the opt-in, keep-meaningful-decimals and unchanged-output requirements.
